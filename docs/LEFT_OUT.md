## How to regenerate or obtain what is left out

- **Output bundles (`*.tar` in `out_*`, `npz_*`).** Each is the packed form of the folder it lies in; the build
  checks that every member is stored next to it under the same name with the same size. Nothing is lost.
- **Input bundles (`*.tar` in `vm_in_*`).** The code and inputs as sent to the cloud machine at launch, with the
  wheels and the launch scripts. The package holds the `code/` and `inputs/` folders instead. In seven of the
  ten bundles one to three files of `code/` were corrected after the launch; the package has the corrected
  form, and each correction is recorded with its time in `patches_*/` and `DEVIATIONS.md` of the run. The
  as-launched bundles are available from the author on request.
- Checksum lists of the runs (`OUT_SHA256SUMS.txt`, `SHA256SUMS.txt`, `CODE_SHA256_*.txt`) name some of the
  files that are left out; a checksum run reports those as missing, and every other file should match.
- **Wheels.** `pip download physics-tenpy==1.1.0` (the hashes are recorded in each `vm_in_*` folder).
- **Operation logs of the laptop.** Not regenerable and not needed: they record how the cloud machines were
  started and stopped. The logs of the computations themselves (`*.log`, `run_log.txt`, `*_stdout.txt`) are in.
- **Neural models (`real_data/f1_neural/`).** `phase3/full_runs/real_data/code/README_predict_learn.md`, section
  on the cost of the neural models: `run_learn.py --stage=f1_mlp57 | f1_mlp115 | f1_ibm57` (8 to 18 hours each).
- **DMRG states, certificates, emulation, device runs.** Stored outputs are in; re-computing them needs the
  cloud machines or a quantum processor. Each run folder has its `DECLARATION.md` and `code/`;
  `phase3/full_runs/real_data/e1/HOW_TO_COLLECT.md` describes the 8-hour run of the certificates added after
  the declaration.
- **Scripts that start and steer the cloud machines (`code/vm/`).** Left out because they name the author's
  machines, key file and folders outside this project. They hold no analysis: they copy `code/` to a machine,
  start the scheduler of that folder (`run_all.py`, `run_v2.py`, `sched.py` ...) and fetch `out/` back.
- **Records of the hosting service with e-mail addresses.** `https://api.github.com/repos/bjader/quantum-groundstate-learning`
  and `.../commits/6b8866b66d62aaf3ee815cd14fa58e9bf4629d66` return them again.
- **Review reports and scratch folders.** Internal; the cited outputs and their scripts are in.
- **Earlier renders of the figures.** `paper/figures/*.py` (matplotlib, PyVista) regenerate them; the documents use
  the native PGFPlots/TikZ versions only.
